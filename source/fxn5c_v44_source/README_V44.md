# FXN5C v0.44 车头过渡面与购买图标修复

本轮修订红色 FXN5C0001 原型车的前角过渡斜面与前脸扶手，并统一全部购买图标。国铁、金温量产车型的几何、车号、动力参数、走行部及百叶动画不变。

## 修改与参考

原型车窗区两侧的红色过渡面改为真实共面的斜面。依据用户实拍的高光边界与轮廓修正折角，保留连续后倾的窗区、内凹窗、黑色分界线、顶部四灯和下方竖排双灯。下部相邻车壳、灯座及完整光学部件跟随安装面调整，避免形成台阶或遮挡灯口。前脸扶手改为竖直杆，并保留与车壳连接的底座。两侧金色“复兴”沿用 v0.43 的实体浮雕。

购买图标从斜视改为水平整车侧视，带简洁轨道展示。13 个购买资源包含 10 台量产车、1 台红色原型车和 2 个量产菜单；各有两种 UI 尺寸及双倍像素版本，共 52 个 TGA。参考本地 FXN3B 的尺寸：小菜单 178×56 / 356×112，紧凑菜单 64×20 / 128×40。轨道为项目程序生成的展示几何，仅进入图像，不随包分发游戏原装 Stage 资源。

原型车原有两个 PNG 图标替换为四个 TGA。游戏日志实际请求 `ui/models_small/vehicle/train/fxn5c_prototype_0001.tga` 并报缺失，PNG 不能满足该路径。原型车的独立购买资源、名称、非编组限定设置及无年代限制均已存在；保留原注册方式，不以修改模型年代或增加重复购买项掩盖加载问题。

照片拟合的斜面、尺寸及光照表现不是厂家测绘数据。参考照片、绘画和字体二进制不收入源码包。

## 验证边界

检查包括原型车三档最终源场景与三档 v0.43 基线、最终原生模型回读、安装界面、邻接边、灯口、前扶手、原生资源引用、52 个图标的尺寸和方向，以及 ZIP 成员与哈希。量产车的几何资源逐文件不变，所有 272 个运动接口网格及动画文件不变。资源检查和离线预览不等同于游戏购买、灯光方向或过弯实测。

包内既有验证记录描述构建候选。公开副本仅更新发布文案及源码中的路径元数据，游戏原生资源保持逐文件一致；发布状态与附件校验以 v0.44 Release 为准。购买菜单仍需完整重启游戏后确认。

## 可编辑源码与重建

源码包是原型车增量 SourceKit，保持两个相邻目录：

- `fxn5c_v43_source`：三个原型车基线场景、清单、必要贴图及完整基线游戏资源。
- `fxn5c_v44_source`：三个最终原型车场景、完整候选游戏资源、建模/导出/审计/图标脚本及贴图。

近景为 `fxn5c_prototype_0001_source.blend`；中远景为 `runtime/final44_fxn5c_prototype_0001_lod1.blend` 和 `lod2.blend`。量产车可编辑场景继续使用 v0.42 完整源码包。本轮不重复收录量产场景，不导出 FBX。

权威入口为 `build_v44.py`，局部几何由 `prototype_geometry_v44.py` 控制。直接修改最终场景不会自动回写生成器，需要同步脚本。保留上述相邻目录结构和原始基线，使用 Blender 5.2 和 `requirements.txt` 的 Python 依赖，在副本中构建：

1. Blender 后台运行 `build_v44.py`。
2. Python 运行 `verify_v44.py`，生成核对后的原生资源回读映射。
3. Blender 后台运行 `render_v44.py -- --style all --icons` 生成全车号图标原稿，再运行 `ui_icons_v44.py` 编码。针对性预览另用 `render_v44.py -- --style prototype --views front cab_side cab_corner side`，加 `--raking` 可观察斜光下的平面。
4. 再运行 `verify_v44.py`，随后 Blender 后台运行 `audit_source_v44.py`。
5. Python 运行 `package_v44.py`。最终清单、模型或图标有改动必须重新核验。

包内包含初始 staging 布局；清空时先复制随包 v0.43 的完整 staging 再构建。本流程依赖已明确收录的历史原型基线，不是从零生成全部历史资源；尚未在全新解压环境验证完整重建。个人运行库不随包分发。

## 使用与许可

备份旧版后安装，完全退出并重新启动游戏，不在旧运行实例里只刷新购买窗口。启用正确的 FXN5C 本地模组，在测试地图购买菜单清空搜索及过滤后搜索“0001”或“红色原型车”。原型车是独立项，不在国铁/金温量产变体展开列表中。不要同时启用资源 ID 相同的本地版与工坊版。
